Tiling plan editor — User documentation

Getting started

The editor opens without a plan. Choose Load template to load the integrated “Tiling Bathroom” example, or use Upload plan to open a YAML or SVG plan. The canvas and controls are generated from the current plan data.

Preview navigation

Use the preview to inspect and edit the plan visually. Use the + and − controls to zoom and Fit to fit the drawing into the available preview. The canvas can be panned, and touch devices support pinch zoom.

Selecting and moving walls and elements

Select a wall or an element directly on the canvas. Selected items can be dragged to a new position. Positions are stored in whole millimeters. Elements are constrained to their wall outline while dragging.

Drawing controls

The sidebar contains the editable tile patterns, walls, and wall elements. Expand a section to edit its values. Use the pencil beside a name to rename it. Walls and elements can be added, removed, reset, and reordered within their own level using the drag handle.

Labels and Dimensions under Display options control the annotations shown on the canvas.

Tile patterns

Tile patterns define tile width, tile height, border size, tile color, border color, and pattern placement. A texture image can replace the tile color. When a texture is present, Random texture rotation can rotate individual tiles by deterministic 90° steps while keeping the layout stable between redraws.

3D preview

Turn on 3D preview to see the surfaces in space. Drag to orbit, Shift-drag or right-drag to pan, and scroll or pinch to zoom. Fit room and the camera presets help you inspect the scene. Click a wall, floor, or element to select its sidebar controls.

Open 3D placement inside each wall section to choose a vertical wall or horizontal floor, then set its X/Y ground position, Z elevation, and angle around Z. The floor lies on the XY plane. These positions are separate from the unfolded 2D drawing. Older plans receive suggested positions; verify and edit them to assemble your actual room. Elements start as simple boxes: their 3D depth / floor height sets the projection from a wall or height above a floor.

The 3D materials use the same pattern offsets, rotation, grout, textures, and pattern regions as the 2D view. YAML preserves all 3D placement and depth values. PNG export continues to export the 2D drawing.

3D light placement lets you add and remove directional lights and edit each light’s color, intensity, and Position and Aim coordinates in millimeters. Default and newly added lights aim at the floor’s center in world coordinates. Intensity starts at 2.5; set it to 0 to turn off a directional light. Turn on Light sources in the 3D toolbar to show gold source markers, turquoise aim markers, and direction helpers. Fit room frames the room while preserving the current viewing angle. The Perspective, Top, and Front buttons select a new viewing angle. All light settings are saved with the plan; the soft hemisphere lighting stays active.

YAML source

Turn on YAML source to edit the plan as YAML, then choose Apply YAML to apply the changes. Side by side shows the preview and source together. YAML source mode and side-by-side mode are mutually exclusive toggles.

The YAML stores the plan name, patterns, walls, outlines, and elements. Canvas bounds are derived automatically from the plan geometry and therefore are not stored as a canvas block. Walls without elements omit the objects property.

Import and export

  • Upload plan imports YAML or SVG.
  • Download YAML saves the editable plan data.
  • Download SVG exports the drawing as vector artwork.
  • Download PNG exports the current rendered canvas as an image.
  • Copy source copies the current YAML source to the clipboard.

Reset and action log

Reset all restores the plan to its established reset point. Individual wall and element reset controls restore those items to their corresponding baseline. The Action log below the editor records semantic editing actions and can be cleared without changing the plan.

Plan coordinates

Editor dimensions and positions are expressed in millimeters. Canvas bounds are recalculated from the current geometry, so moving or changing the plan does not require manually maintaining viewport dimensions in YAML.

Tiling plan editor — Developer documentation

Architecture

The editor is a TypeScript browser application built with Vite. PlanService owns the authoritative normalized plan data and emits semantic change events. EditorState contains transient UI state. CanvasViewport, CanvasRenderer, and HitTester handle viewport conversion, Canvas 2D rendering, and plan-space picking. ControlPanelView renders the sidebar with Preact. Signals expose the effective persistent or transient plan to both preview renderers and YAML. YamlCodec and SvgCodec are serialization boundaries, while EditorApp coordinates document lifecycle and model changes.

Plan data

The runtime model is plain JavaScript data. A plan contains a name, units, patterns, and walls. Walls contain position, rotation, an outline, and optionally objects. Objects are wall-local rectangles. Pattern dimensions are derived from tileWidth + borderSize and tileHeight + borderSize.

Canvas bounds are derived at runtime from geometry and are not part of the YAML contract. Legacy YAML canvas blocks are accepted and ignored. Empty wall object collections are omitted from YAML.

Mutation flow

Persistent edits go through PlanService. Signals drive rendering and YAML synchronization. Semantic operation events drive the action log and baseline bookkeeping. Drag previews update only the transient plan and commit once on release.

Canvas interaction

Pointer coordinates are converted through the viewport into plan space. Dragging uses a transient plain-data snapshot and commits the final whole-unit position to PlanService on pointer release. Object movement is converted into wall-local coordinates and constrained to the wall polygon. Pan, zoom, fit, and pinch are independent of serialization.

Rendering

The preview is rendered directly with Canvas 2D. Tile patterns are clipped to wall outlines. Textures replace tile color when present, and optional deterministic quarter-turn rotation is derived from tile-grid coordinates.

YAML codec

YamlCodec is an import/export boundary. YAML is the prefered way of sharing a model.

SVG codec

SvgCodec is an import/export boundary. Export derives its view box from current geometry.

Controls and selection

The sidebar uses native disclosure sections. Selection coordinates canvas state with the matching wall or object controls. Name editing uses temporary text inputs; Enter commits, Escape cancels, and edit-control pointer events are isolated from the surrounding disclosure summary. Reordering is constrained to items at the same structural level.

Reset behavior

Loading a template or uploaded document establishes the reset baseline. Wall and object snapshots preserve their loaded state. Applying YAML changes the current document without redefining that baseline. Newly added items establish their own initial reset state.

Document lifecycle

Startup creates an empty document. The integrated Tiling Bathroom YAML is loaded only when requested. Upload accepts YAML or SVG. Downloads are generated from the current authoritative plan as YAML, SVG, or rendered PNG.

Extending the editor

For persistent properties, add normalization and mutation support in PlanService, then update YAML and SVG serialization only when the property belongs to those interchange contracts. Rendering-only state should stay outside the persisted model. Controls should call model mutations rather than forcing canvas redraws directly.
